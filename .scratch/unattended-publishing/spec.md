# Spec：三平台个人账号无人值守发布

Status: ready-for-agent
Tracker: local Markdown

版本：2026-09-26。正文由本次对话、代码级需求审计及离线测试结果综合生成；测试边界、15 张票及依赖已由用户确认，现已发布到本地 Markdown tracker。

## Problem Statement

个人内容创作者希望把自己的原创视频和图文自动发布到抖音、小红书、微信视频号，每个平台只运营一个账号。内容和发布时间准备好后，应由本机程序完成上传、填写、提交和结果查询，常态运行不需要人工参与。

现有上传工具能操作发布页面，但不足以承担可靠的无人值守执行：它可能替内容选择不准确的 AI 或转载声明，在页面响应较慢时重复点击发布，把页面跳转或按钮消失当作成功；进程崩溃后也缺少能够判断“是否已经提交”的持久记录。使用者因此无法确定作品是否发出、是否重复、是否发到了正确账号，以及内容与输入是否一致。

使用者需要的是可追溯、可恢复的发布过程。页面验证、会话失效和提交结果未知都必须成为明确状态，避免程序继续进行不确定的发布操作。账号风控概率和平台最终审核行为不由本系统控制，不能以“脚本执行完成”代替这些结果的证明。

## Solution

在现有 CLI、请求模型和平台上传适配器上增加统一任务生命周期。使用者提交一份内容清单，为每个目标平台生成独立任务；系统检查账号、素材和元数据，持久记录执行过程，串行完成发布，并返回可以查询的任务编号和结构化结果。

一旦发布动作可能已经送出，系统通过只读方式核对平台作品。无法确认时保持“提交结果未知”，不重新发布。发生登录或安全验证时暂停对应账号，其他账号仍可继续执行。系统保留明确的人工维护入口，但无人值守运行不等待终端输入，也不依赖人工处理后才能返回结果。

首版支持以下范围：

| 平台 | 内容类型 | 执行时间 |
|---|---|---|
| 抖音 | 视频、图文 | 立即执行、本地到时启动 |
| 小红书 | 视频、图文 | 立即执行、本地到时启动 |
| 微信视频号 | 视频 | 立即执行、本地到时启动 |

首版不开放平台后台预约发布。需要该能力时，应另行验证页面设置与读回；本地到时启动不意味着作品在那个时刻已经公开。

## User Stories

1. As a 个人内容创作者, I want 在本机安装项目后直接使用三个目标平台的命令, so that 我不必为未使用的平台安装无关依赖才能启动工具。
2. As a 现有 CLI 用户, I want 已使用的命令参数继续保持其含义, so that 升级不会悄悄改变我的发布策略。
3. As a Python 集成使用者, I want 受支持的旧位置参数继续正确绑定, so that 新增合集等字段不会把定时模式或浏览器设置传错。
4. As a 内容创作者, I want 一次提交内容清单并选择目标平台, so that 我可以自动完成同一原创内容的跨平台分发。
5. As a 内容创作者, I want 每个平台返回独立的任务编号和状态, so that 一个平台失败不会掩盖其他平台的成功。
6. As a 内容创作者, I want 在上传前检查素材是否存在、类型是否受支持以及内容是否完整, so that 无效任务不会占用账号和浏览器。
7. As a 内容创作者, I want 执行前确认素材未被替换, so that 发布的始终是我提交时选定的版本。
8. As a 内容创作者, I want 分别指定标题、正文、话题、封面和支持的合集, so that 各平台作品能准确表达我的内容。
9. As a 内容创作者, I want 超长标题或过多话题得到明确的字段错误, so that 系统不会悄悄截断我的输入。
10. As a 内容创作者, I want 话题按准确含义匹配且失败时保留正文, so that 搜索候选或编辑器异常不会改变我的内容。
11. As a 原创作者, I want 内容归属与 AI 使用情况独立声明, so that “原创”不会被自动等同于“未使用 AI”或“使用了 AI”。
12. As a 原创作者, I want 没有明确要求时不被自动标记为转载或 AI 生成, so that 平台上的来源声明符合内容事实。
13. As a 内容创作者, I want 平台要求但我尚未提供的声明在提交前被指出, so that 系统不会代我猜测事实。
14. As a 内容创作者, I want 必需声明、封面或合集设置失败时阻止发布, so that 不完整的作品不会被误发。
15. As a 内容创作者, I want 只有明确允许的可选字段可以降级并记录原因, so that 我能知道实际发布内容与请求之间的差异。
16. As a 账号持有人, I want 将任务绑定到稳定的平台账号标识, so that 即使会话文件放错也不会发布到其他账号。
17. As a 账号持有人, I want 开始编辑前和最终提交前都核对账号身份, so that 中途切换或失效的会话不能误发内容。
18. As a 账号持有人, I want 三个平台使用相互隔离的会话, so that 一个账号的维护不会污染另一个账号。
19. As a 账号持有人, I want 同一账号同时只执行一个会话写入流程, so that 上传、登录维护和多进程执行不会互相干扰。
20. As a 自动化使用者, I want 重复投递同一请求得到同一个任务, so that 调度器重试不会创建重复作品。
21. As a 自动化使用者, I want 同一个幂等键被用于不同内容时得到冲突错误, so that 输入错误不会被误当成合法重试。
22. As a 内容创作者, I want 系统确认所有素材都上传并处理完成后再发布, so that “已选择”或标题框出现不会掩盖未完成的上传。
23. As a 图文创作者, I want 系统核对全部图片的成功数量和失败项, so that 十张图片只成功九张时不会发布残缺内容。
24. As a 自动化使用者, I want 一次发布尝试最多执行一次最终提交动作, so that 页面响应慢不会引发重复点击和重复发布风险。
25. As a 自动化使用者, I want 提交回执丢失时先查询作品结果, so that 已送达的平台请求不会被当作从未提交而重发。
26. As a 自动化使用者, I want 找不到可靠作品匹配时保留“提交结果未知”, so that 不确定性不会被包装成成功或可重试失败。
27. As a 内容创作者, I want 区分平台已接收、审核中、已发布、被拒绝和草稿, so that 我能知道作品的真实进展。
28. As a 自动化使用者, I want 进程退出或电脑重启后继续查询已有任务, so that 已完成工作和提交记录不会丢失。
29. As a 自动化使用者, I want 提交前中断与提交后中断采用不同恢复策略, so that 恢复执行不会重新发送可能已经发表的作品。
30. As a 自动化使用者, I want 旧执行进程尚未停止时禁止新进程接管账号, so that 锁超时不会造成两个执行器同时发布。
31. As a 账号持有人, I want 遇到扫码、短信、实名或未知安全提示时暂停对应账号, so that 程序不会继续尝试不确定的操作。
32. As a 自动化使用者, I want 无人值守过程永远不等待 stdin 或人工扫码完成, so that 任务能在有界时间内返回明确的受阻状态。
33. As a 自动化使用者, I want 一个账号暂停后其他平台仍能处理任务, so that 单个平台的问题不会阻塞全部分发。
34. As a 自动化使用者, I want 每个阶段都有截止时间且可以取消, so that 页面故障不会让浏览器无限运行。
35. As a 自动化使用者, I want 临时故障仅在能够确认未提交时进行有界重试, so that 重试策略不会把提交未知变成重复发布。
36. As a 自动化使用者, I want 取消、异常和资源关闭失败时仍释放已创建资源, so that 一个失败任务不会破坏后续任务。
37. As a 内容创作者, I want 用明确时区指定本地启动时间, so that 电脑时区与内容受众时区不同也不会导致计划错时。
38. As a 内容创作者, I want 请求首版不支持的平台预约或视频号图文时得到明确拒绝, so that 不支持的功能不会被静默忽略或变成立即发布。
39. As a 自动化集成使用者, I want 读取稳定的 JSON 结果和退出状态, so that 我的调度工具不需要从日志文案猜测成功。
40. As a 自动化集成使用者, I want 用任务编号追踪每次尝试、状态变化和结果证据, so that 我能定位失败阶段并确定是否可能已经提交。
41. As a 账号持有人, I want 日志和普通诊断输出不包含 Cookie、验证码或登录二维码, so that 排查问题不会泄露账号访问凭据。
42. As a 维护者, I want 浏览器和驱动版本可追踪、会话更新可恢复, so that 升级造成的问题能够定位和回退。
43. As a 维护者, I want 通过公共任务接口验证发布次数、任务结果与恢复行为, so that 内部重构不会迫使测试跟着函数实现一起改写。
44. As a 维护者, I want 使用无真实账号的离线场景复现延迟、断连、验证、崩溃和并发竞争, so that 每次变更都能验证最重要的失败路径。
45. As a 内容创作者, I want 系统明确区分已验证能力与尚未验证的平台行为, so that 我不会把离线测试通过误认为账号永远不会触发风控。

## Implementation Decisions

1. **范围与部署。** 面向一台 Windows 主机、三个个人账号，保留现有 Python CLI 和浏览器上传适配器。首版单 worker 串行执行；账号受阻后跳过其待执行任务，继续处理其他可运行账号。该规格不建设通用矩阵运营平台。

2. **统一领域词汇。** 发布清单描述期望内容；任务是一个平台和一个账号上的一次交付意图；尝试记录某次执行；事件记录状态变化；平台作品是远端交付对象；账号状态与任务状态分别管理。任务重试不产生新的交付意图。

3. **优先复用现有边界。** 保留请求模型、parser、dispatch、独立登录/检查入口以及各平台素材填写能力。新增的任务编排层协调持久化与阶段执行，平台适配器继续负责页面细节。不能把 legacy Web 登录 SSE 队列视为发布任务队列。

4. **安装和兼容。** 按选择的平台延迟加载适配器，并完整声明实际依赖。清理陈旧打包项，为无账号环境提供可执行的配置初始化流程。旧 CLI 参数及受测构造器位置参数保留语义；新增可选构造参数采用关键字。结构化返回值属于明确的接口升级，需要记录迁移方式，不能偷偷以另一种对象替代原返回值。

5. **输入清单。** 清单包含交付键、目标平台、绑定账号、素材摘要和版本、标题正文话题、可选封面/合集、内容归属、AI 使用事实、需要设置的声明及字段降级策略。规范化后保持不可变；不能在页面填写函数中修改原始请求。平台必填信息缺失时在提交前明确失败。

6. **持久化模型。** 使用 SQLite 保存任务、尝试、事件和账号绑定。状态与相关事件在事务中更新。采用平台、账号、幂等键组合唯一约束；重复请求返回已有任务，相同键配不同清单拒绝为冲突。素材摘要和清单版本用于核查一致性，不替代交付键。跨平台交付分别入库，已经成功的平台不因其他平台失败而重发。

7. **锁与所有权。** 进程间账号锁覆盖上传及会话维护，最终提交前再次检查任务所有权。租约超时不能证明旧进程已失去发布能力；不能确认旧 worker 和浏览器已终止时，拒绝新的写入接管。首版不依靠分布式队列解决单机串行问题。

8. **账号正向校验。** 会话必须提供目标平台稳定账号 ID 的正向证据。昵称、头像、URL 和“未出现登录框”不能单独作为身份依据。开始写入和最终提交前都校验预期账号；无法确定或不匹配时停止。登录和账号绑定属于独立维护操作，不由上传任务自动选择或切换账号。

9. **内容声明。** 删除无依据的 AI 默认值和无条件转载选择。原创归属、AI 使用和平台权益声明相互独立；根据清单事实映射平台控件。不提供可选声明时不修改，平台当前要求必填却缺少事实时返回字段错误。指定声明设置失败或最终读回不符，禁止提交。

10. **元数据与素材就绪。** 对标题、正文、话题、封面、合集和图片数量验证最终结果。超限输入显式拒绝或按调用者明确选择的转换策略处理。用户指定的必需字段默认不能降级；允许降级时记录实际应用值和警告。视频/图片处理完成必须有对应页面状态证据；编辑器可用不等于素材就绪。

11. **提交边界。** 在可能发出最终提交动作之前持久化 SUBMITTING。每次尝试最多一次最终提交；已识别的多阶段确认分别记录阶段。取消超时后重新 click、改用脚本再点等无法证明前次无效的回退。提交动作可能已送出但证据不充分时进入 UNKNOWN_COMMIT。

12. **作品核对。** 通过平台只读作品列表/详情核对结果，优先使用可靠作品 ID，再结合账号、素材特征、内容及提交时间范围。仅标题相同或暂未查到作品不能作为确定结论。多个候选、回读不可用或字段不足均保持不明。UNKNOWN_COMMIT 不能自动回到待发布队列。

13. **状态语义。** 任务执行状态涵盖排队、准备、就绪、提交中和提交前失败；平台结果区分已接收、审核中、已发布、拒绝、草稿及未来扩展的预约成功。账号分别记录正常、认证暂停和页面变化暂停。审核拒绝不能归类为可自动重投的网络错误；普通页面跳转不构成已发布证据。

14. **恢复与取消。** 提交前确定未产生远端副作用的临时故障可以有界重试；提交后崩溃、客户端断连以及可能送出时发生的取消都转入不明结果核对。无法证明动作未发送时采用保守状态。任务取消不宣称已撤销远端作品。

15. **挑战与未知页面。** 扫码、短信、实名验证、未知安全提示和账号不符均结束当前尝试并暂停对应账号；任务不读取 stdin，不循环索取验证码。仅允许关闭明确识别的普通引导层，禁止批量移除未知浮层后强行提交。无响应时暂停可持续存在，系统不保证挑战后自动恢复。

16. **截止与资源。** 所有阶段共享总截止时间并有阶段预算，采用单调时钟。创建浏览器即进入资源保护范围；会话创建、脚本初始化、登录态保存、关闭失败及取消都必须清理已创建资源。清理错误附加记录，不能掩盖原始业务错误。页面关闭和 UI 变化不吞为无限等待。

17. **机器结果。** 增加稳定的结构化结果，至少提供任务和尝试标识、账号/平台、状态、提交是否确定发生或仍不明、作品标识、已核实时间、实际元数据、警告、错误类别和证据引用。未获得的数据为空，不猜值。机器输出模式下 stdout 只输出结果，诊断走 stderr；退出状态与结果语义一致。不能仅凭独立 retryable 标志越过提交边界。

18. **会话与可观测性。** 集中管理浏览器生命周期、固定版本和独立会话目录，会话更新采用原子替换。先保留可验证的现有 storage-state 路线；完整持久 profile 迁移单独验证，避免同时变更驱动、会话和提交逻辑。凭据按本机用户权限隔离；日志和证据按任务关联，脱敏并设置保留策略，关闭可能泄漏局部变量的生产诊断输出。

19. **时间语义。** 本地 run_at 使用显式 IANA 时区并保存 UTC 时刻。运行中对时间和会话等前置条件复核。首版拒绝平台 publish_at 预约请求，不悄悄改成立即发布。将来开放平台预约时复用已有未来时间校验，同时验证平台窗口、完整年月日时分和页面读回。

20. **平台能力门槛。** 五条内容路径分别声明支持状态。账号稳定 ID 与作品只读核对字段必须在接入早期验证；不能实现可靠识别的路径保持受限或受阻状态，不能降低成功判据以通过验收。界面变化应定位为适配问题并留下证据。

21. **实现顺序。** 先修安装与兼容性基线；随后建立内容清单、结果协议、最小事务记录和提交边界；再完成恢复、锁、挑战停止、截止和资源回收；最后收敛会话、故障测试和平台验证。原审计 R01–R07 是首版上线门槛，测试对应所有门槛；R08 先完成管理收敛，持久 profile 迁移可独立交付。

## Testing Decisions

**已确认的主要测试边界：统一 CLI/任务接口。** 复用现有 parser/dispatch 作为输入边界，驱动完整任务生命周期。多数测试通过真实任务数据库、可控时钟和有状态平台替身验证外部可观察结果，不再为每个内部 helper 新建测试边界。只对难以从该层验证的平台 DOM 行为、进程终止和资源清理保留必要补充测试。

好测试验证输入与结果的关系：同一任务是否只产生一次最终提交、返回状态是否准确、发布内容是否一致、崩溃后是否恢复正确、账号是否被正确阻断。不要把固定 sleep 毫秒、私有函数调用顺序或内部实现名称当主要断言。

测试范围覆盖任务编排、持久化、账号所有权、结果核对、五条平台发布路径、公共 CLI 输出，以及会话资源与诊断处理。已有 unittest/pytest、AsyncMock、CLI 参数测试和本地 HTML 弹窗测试是先例；修复落后夹具后在这些基础上扩展。

| 场景 | 主要外部验收 |
|---|---|
| 干净安装、未使用平台缺可选依赖、旧命令/位置参数 | 目标 CLI 可启动且原参数含义不变；不修改错误期望以掩盖回归 |
| 同一交付键重复请求、同键不同清单、跨平台部分成功 | 返回同一任务或明确冲突；成功平台不重发 |
| 原创非 AI、原创 AI、缺必填声明、错误话题候选 | 声明准确；必需项失败时远端提交数为 0；正文不受损 |
| 视频仍处理、图片缺失、标题先出现、上传永久卡住 | 就绪前不提交；到期返回明确失败而非无界等待 |
| 点击已生效但响应延迟、断网、按钮消失、错误页跳转 | 最终提交数不超过 1；不能依据页面变化返回 PUBLISHED |
| 作品单一匹配、多候选、列表延迟、只读核对不可用 | 返回已证实状态或保留 UNKNOWN_COMMIT；后者不重新上传 |
| 各阶段杀进程并重启 | 提交前按条件恢复；SUBMITTING 后只读核对且不重复提交 |
| 两进程争抢账号、租约到期但旧进程仍存活 | 同账号只有一个写入者；不能仅凭到期接管 |
| 错误账号、空白页、会话失效、任意阶段验证弹窗 | 无提交；在有界时间内返回受阻并暂停对应账号；其他账号可运行 |
| 任务取消、context 创建或关闭失败、状态保存失败 | 已创建资源被释放；保留原始错误；可能已提交时保持不明 |
| 显式时区、跨日、夏令时歧义、不支持的预约参数 | 时间含义明确；无静默时区转换或立即发布回退 |
| 日志混入验证码/Cookie、机器模式输出诊断 | 普通输出无凭据；JSON 可解析且与持久状态一致 |

多数测试不依赖浏览器或账号；本地 DOM 测试只使用静态测试页面。真实数据库与子进程用于崩溃/锁验证，不以数据库 mock 证明持久性。默认测试不持有真实会话，不连接三个平台创作者后台，不发生真实发布。

验收顺序为公共契约和恢复测试、本地 DOM 测试、平台只读能力验证、明确授权的少量真实发布验证。每一条目标路径分别通过；一个平台通过不替代其他平台。离线通过不能证明封禁概率、审核结果或长期页面兼容性。

## Out of Scope

- 官方发布 API、认证绕过、验证码破解、伪装设备或“零风控”承诺。
- 海外平台、多账号矩阵、账号注册、养号、互动自动化、内容生成及大规模分发。
- 微信视频号图文，以及首版的平台后台预约发布；不支持的请求必须明确拒绝。
- 重建或上线 legacy Web、对公网提供任务 API、多用户权限体系和移动 App。
- Redis/Celery/Kubernetes 等分布式基础设施。
- 自动选择其他账号、自动跨设备轮换，以及在挑战出现后保证无人处理仍恢复发布。
- 自动删除已经发表的作品来回滚跨平台部分成功。
- 首版强制迁移完整 persistent profile、同时更换所有浏览器驱动。
- 把所有历史 uploader 和 legacy Web 缺陷一并修复；仅保留兼容性所必需的改动。
