# 13 — 一份清单分发到多个平台，部分失败可独立追踪

**What to build:** 使用者一次选择多个目标平台，获得逐平台任务及汇总视图；某个平台失败或暂停时，其他平台照常执行，重试不会重发已成功的目标。

**Blocked by:** 04 — 发布前验证不可变清单、素材版本和声明事实；05 — 提交后失联或崩溃时只核对结果，不重新发布

**Status:** done

**来源:** 《三平台个人账号无人值守发布》规格；用户故事 4、5、20、21、33、39、40；代码审计需求 R04、R07。

- [x] 跨平台提交按规范化清单创建独立交付任务，每个平台/账号保持稳定交付键和自己的状态。
- [x] 重复提交同一批请求返回原任务集合；同键不同内容明确冲突，不静默覆盖已排队任务。
- [x] 公共查询展示各目标 job_id、当前状态、错误与证据；不能用统一成功覆盖部分失败。
- [x] 目标账号暂停或不支持所选内容类型时，其结果明确可见，其他有效目标可继续处理。
- [x] 对确定未提交的失败目标进行重试时，不重发成功目标，也不重新提交 UNKNOWN_COMMIT 目标。
- [x] 不会自动删除已发作品来回滚部分成功；通过受控多平台目标验证交付次数和持久恢复。

**测试边界:** 以已经确认的公共 CLI/任务接口为主；只有平台页面、进程终止和资源回收等必要场景增加本地测试。验收观察结果与交付行为，不绑定私有实现细节。

**实施与验收:** `f4d9f76`、`da9bb22`。最终完整测试 236 项与 20 项子测试通过，所选范围类型检查 0 错误、0 警告；Standards / Spec 独立复审均无未关闭项。验证记录：`docs/audit/ticket-06-12-13-validation.md`；审查记录：`docs/audit/ticket-06-12-13-review.md`。本地浏览器、预检子进程、真实 SQLite、定时与批次恢复均已验证；真实账号发布未验证。数据库 schema v3 防止旧 v2 worker 忽略计划时间；平台预约仍 UNSUPPORTED。
