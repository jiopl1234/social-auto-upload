# 03 — 串行执行任务，同账号只允许一个写入者

**What to build:** 使用者启动 worker 后，待执行任务进入一次可查询的执行流程；多个进程竞争时仍保持账号单写入，维护会话也遵守相同锁，受阻账号不拖住其他账号。

**Blocked by:** 02 — 提交清单后获得可持久查询、可去重的单平台任务

**Status:** in-progress

**来源:** 《三平台个人账号无人值守发布》规格；用户故事 18、19、30、33、39；代码审计需求 R04、R05、R08。

- [ ] 公共 run/status 贯通领取任务、创建 attempt、状态和事件更新、返回结果；用受控测试目标验证执行，未接入真实平台不能旁路发布。
- [ ] 单 worker 默认串行；两个进程不能同时对同一账号执行写入，任务领取与所有权更新具有事务约束。
- [ ] 账号锁同时覆盖支持的登录/会话维护入口；账号会话相互隔离，其他账号的维护不修改本账号状态。
- [ ] 租约超时但旧 worker 或浏览器仍存活时拒绝新的写入接管；不能只靠超时推断安全。
- [ ] 提交动作执行前可验证当前任务所有权；失去所有权的执行器不再写入。
- [ ] 账号暂停会跳过其待执行任务，其他可运行账号继续执行；暂停原因可通过查询读取。
- [ ] 使用子进程竞争和真实数据库验证单写入行为，不用纯 mock 证明互斥。

**测试边界:** 以已经确认的公共 CLI/任务接口为主；只有平台页面、进程终止和资源回收等必要场景增加本地测试。验收观察结果与交付行为，不绑定私有实现细节。
