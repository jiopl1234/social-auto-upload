# 05 — 提交后失联或崩溃时只核对结果，不重新发布

**What to build:** 使用者能在任务中断后恢复查询，系统区分提交前失败与可能已经提交；后者只读核对远端结果，无法确认时保留 UNKNOWN_COMMIT。

**Blocked by:** 03 — 串行执行任务，同账号只允许一个写入者

**Status:** in-progress

**来源:** 《三平台个人账号无人值守发布》规格；用户故事 24、25、26、27、28、29、35；代码审计需求 R03、R04、R07。

- [ ] 在最终提交动作可能送出前，事务写入 SUBMITTING 与尝试记录；每次尝试最多一个最终提交动作。
- [ ] 延迟响应、点击回执丢失、提交后异常和进程终止都进入明确的提交不明状态，不自动重新上传或重新点击。
- [ ] 只读核对支持已证实作品、多个候选、尚不可见、接口不可用等结果；证据不足保持 UNKNOWN_COMMIT，不把暂时查不到当作未提交证明。
- [ ] 已接收、审核中、已发布、拒绝和草稿可被分别查询；URL 或按钮变化不单独构成已发布证据。
- [ ] 确定未提交的临时错误才允许配置内重试；身份、声明、UI 变化、审核拒绝不作为网络重试。
- [ ] 提交前和提交后分别终止子进程，重启后按边界恢复；连 SUBMITTING 之后是否已点击也无法证明时采用保守路径。
- [ ] 公共任务接口配合有状态测试目标证明交付数不超过 1、事件与查询一致；不声称平台远端 exactly-once。

**测试边界:** 以已经确认的公共 CLI/任务接口为主；只有平台页面、进程终止和资源回收等必要场景增加本地测试。验收观察结果与交付行为，不绑定私有实现细节。

**实现提交:** `d72900b`。持久提交边界、单次最终动作、只读作品核对、有界提交前重试、崩溃恢复及 v1 数据库升级已实现。

**验证:** 审查修正后 04/05 集成测试 156 项与 20 项子测试通过，相关 Pyright 0 错误。详见 [验证记录](C:/Users/Chinese/social-auto-upload/docs/audit/ticket-04-05-validation.md)；四个真实进程用例覆盖边界前后强杀与次数上限，独立持久目标记录交付数不超过 1，恢复保留内容遗漏警告。

**限制:** UNKNOWN_COMMIT 不自动回到发布队列；证据字段不足或时间精度不兼容时保留不明。平台适配器尚未接入，不声明平台远端 exactly-once。超时与取消由 06 号票承接。审查完成前保持 in-progress。
