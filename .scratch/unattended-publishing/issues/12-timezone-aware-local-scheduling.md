# 12 — 按显式时区到时启动任务，重启后不重复触发

**What to build:** 使用者用明确时区设置本地执行时间，worker 在到期后启动一次任务，重启仍保持原计划和交付边界。

**Blocked by:** 05 — 提交后失联或崩溃时只核对结果，不重新发布

**Status:** in-progress

**来源:** 《三平台个人账号无人值守发布》规格；用户故事 28、29、37、38；代码审计需求 R04、R09。

- [ ] 入队接受显式 IANA 时区并记录对应 UTC 时刻，查询同时表达所选时区和启动时间。
- [ ] 本机时区变化不改变任务对应的时刻；跨日、跨月和夏令时重复/不存在时间得到明确处理。
- [ ] 未到期不执行，到期后只领取一次；重启不重新触发已提交或提交不明任务。
- [ ] 本地启动时间不被表述为作品已公开时间，实际开始时间与平台结果时间分别记录。
- [ ] 平台 publish_at 预约请求在首版返回 unsupported，不能丢分钟、偷偷转换或降级成立即发布。
- [ ] 用可控时钟、真实数据库和公共 CLI 验证，避免依赖真实长时间等待。

**测试边界:** 以已经确认的公共 CLI/任务接口为主；只有平台页面、进程终止和资源回收等必要场景增加本地测试。验收观察结果与交付行为，不绑定私有实现细节。

**实施候选:** `f4d9f76`。显式本地时间、IANA 时区、UTC/fold 持久化，未到期拒绝领取、时钟回拨延期及总尝试上限已接入。验证见 `docs/audit/ticket-06-12-13-validation.md`：225 项与 20 项子测试通过，含公共 CLI、可控时钟、DST 和重启核对。当前等待 Standards/Spec 双线审查，未标 done。定时表示本地启动约束，publish_at 仍 unsupported，不保证平台公开时间。
