# 06 — 任务超时或取消后准时退出，并释放浏览器资源

**What to build:** 使用者能够取消或限制运行时间；页面卡住、会话创建失败及资源关闭异常时，任务仍有确定结果，下一项任务能继续运行。平台接入复用这一受测执行行为。

**Blocked by:** 05 — 提交后失联或崩溃时只核对结果，不重新发布

**Status:** in-progress

**来源:** 《三平台个人账号无人值守发布》规格；用户故事 31、32、34、36、42；代码审计需求 R05、R06、R08。

- [ ] 导航、上传、处理、元数据、提交观察与只读核对均受总截止和阶段预算约束，采用单调时钟，不存在无界等待。
- [ ] 取消发生在确定未提交时返回取消结果；发生在可能提交后则保留提交不明并安排只读核对，不宣称远端已撤销。
- [ ] browser 创建成功起即纳入资源保护；context 创建、初始化、保存会话和关闭失败均能清理已创建资源。
- [ ] context.close 抛错时仍执行 browser 关闭；清理异常作为附加诊断，主要业务异常不被覆盖。
- [ ] 页面关闭、账号挑战、UI 不匹配能够按类别有界退出；无人值守执行不读取 stdin、不等待扫码完成。
- [ ] 通过公共任务执行、本地 HTML 和必要故障注入验证结果；测试任务取消或崩溃后，下一任务不受残留资源影响。
- [ ] 平台环境版本及运行参数可由执行结果关联；本票仅收敛现有会话生命周期，不强制更换驱动或迁移完整 profile。

**测试边界:** 以已经确认的公共 CLI/任务接口为主；只有平台页面、进程终止和资源回收等必要场景增加本地测试。验收观察结果与交付行为，不绑定私有实现细节。

**03 号票审查承接:** Standards 提醒三平台旧 CLI 入口重复资源开始/关闭标记，以及小红书/视频号重复的资源关闭与错误优先级代码（两项非阻断 P3）。集中生命周期时收敛这些重复策略，保留整个检查与上传流程的账号锁跨度，并保持内层清理失败不能被外层业务错误处理吞掉的回归测试。

**04/05 号票审查承接:** Standards 提醒 `worker.run_once` 聚合准备、提交、核对和清理阶段（非阻断 P3，Divergent Change）。本票加入阶段预算时提取各阶段操作，协调器仍明确持有持久提交边界与最终状态更新。
