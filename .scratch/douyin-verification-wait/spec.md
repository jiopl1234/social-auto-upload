# 抖音发表后的可见验证等待

Status: done

基线：`a421e15`。用户要求补齐真实 CLI 点击发表后遇到验证时关闭窗口、无法由本人继续的缺口。

沿用用户已确认的 CLI/TaskService 接口和本地平台页面测试边界，按 TDD 实施；完成双轴审查与离线回归后提交当前分支。

1. 新增 `jobs run --verification-wait SECONDS`，默认关闭，开启时须指定单个 `--job` 和 `--headed`，不与 `--prepare-only` 混用。仅开放已有抖音视频能力，范围 1–600 秒。
2. 只处理本次最终发表动作之后出现的认证要求。在同一浏览器、同一任务尝试中有界等待本人处理，不自动填写验证码、移除验证、刷新页面或第二次点击发表。
3. 检测到验证即暂停账号并记录等待事件，保留账号锁和浏览器。CLI 立即在 stderr 提示本人在现有窗口操作，stdout 保持单个最终 JSON 结果。
4. 验证消失后继续等待同次提交的真实回执，重新核对稳定身份并保存会话。只有回执、会话保存和独立作品核对全部成功且清理无异常，才解除本次验证造成的账号暂停；不能仅凭提示消失宣告发布成功。
5. 验证等待使用一个累计期限；重复挑战不重置期限，并始终受既有提交/作品核对阶段、总期限、取消、所有权和清理预算约束。CLI 明确扩展提交及作品核对阶段预算以容纳所配置等待，但两个阶段共享同一验证截止时间，不延长总期限或删除清理预留。
6. 超时、取消、页面关闭、身份不符、缺回执、清理失败均保留保守结果及账号暂停，禁止自动重发。默认未开启等待时仍按原有协议立即暂停和清理。
7. 已失去原浏览器的 UNKNOWN_COMMIT 任务只允许原有只读恢复；不得因新选项而重置、上传、重建任务或再次提交。`2.mp4` 的原任务 `53ac89bdd52e4d73b3d52f36e57170aa` 保持原状，本次代码实施不再公开发布它。
8. 更新使用说明、平台契约和验证记录。离线测试不能替代真实平台验收，`production_verified=false` 保留到完整真实发布确认。
