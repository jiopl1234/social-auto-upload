# 02 — 提交清单后获得可持久查询、可去重的单平台任务

**What to build:** 使用者通过公共 CLI 提交一项平台交付，获得 job_id，并在重启后继续查询；重复交付键返回原任务，同键不同清单被拒绝。首次交付只入队，不触发平台写入。

**Blocked by:** 01 — 干净安装后可运行三平台 CLI，并恢复旧参数语义

**Status:** draft — breakdown approved; pending tracker selection

**来源:** 《三平台个人账号无人值守发布》规格；用户故事 5、20、21、28、39、40；代码审计需求 R03、R04、R07。

- [ ] 公共入口贯通输入解析、SQLite 事务、任务/事件持久化及 JSON 输出；正常入队返回可查询的 QUEUED 任务。
- [ ] 平台、账号和交付键组合唯一；同键同输入返回同一任务，同键不同输入返回明确冲突，不创建第二个任务。
- [ ] 进程重启后，查询仍返回相同任务标识、请求摘要和状态；失败事务不留下半个任务或孤立事件。
- [ ] 约定后续执行所需的任务、尝试、事件、账号绑定与结构化结果语义，字段未获得时为空，不伪造作品 ID。
- [ ] 机器模式 stdout 仅包含可解析结果，错误结果与退出状态一致，日志走 stderr。
- [ ] 使用真实临时数据库从公共入口验证行为；此阶段平台执行返回明确的未接入状态，不把入队当发布成功。

**测试边界:** 以已经确认的公共 CLI/任务接口为主；只有平台页面、进程终止和资源回收等必要场景增加本地测试。验收观察结果与交付行为，不绑定私有实现细节。
