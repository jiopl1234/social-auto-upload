# 07 — 抖音视频完成准确填写、单次提交和作品核对

**What to build:** 使用者提交抖音视频后，系统验证账号与素材、准确应用内容和声明，最多提交一次，并根据可信作品证据返回结果。

**Blocked by:** 04 — 发布前验证不可变清单、素材版本和声明事实；06 — 任务超时或取消后准时退出，并释放浏览器资源

**Status:** draft — breakdown approved; pending tracker selection

**来源:** 《三平台个人账号无人值守发布》规格；用户故事 8、10、11、12、13、14、15、16、17、22、24、25、26、27、31、32；代码审计需求 R02、R03、R05、R06、R07、R10。

- [ ] 接入开始即核查稳定账号 ID 与只读作品识别依据；不能确认的能力保持受限，不用昵称、标题或页面跳转替代可靠身份/作品证据。
- [ ] 编辑前及最终提交前匹配预期账号；空白页、失登录、错误账号和短信验证均阻止提交并返回相应状态。
- [ ] 完整视频流程不再把未指定声明默认改成 AI 生成；显式声明、标题正文话题、指定封面/合集读回一致，否则按必需项/显式可选策略处理。
- [ ] 素材上传和处理完成有实际证据；标题框出现或进度文案不单独构成可发布状态。
- [ ] 使用公共任务提交协议，取消原循环点击及未知浮层强制清理；响应延迟、断连和登录跳转不触发第二次提交。
- [ ] 作品只读核对区分已接收、审核中、已发布、拒绝和不明；缺可靠匹配不能返回 PUBLISHED。
- [ ] 通过公共任务接口与本地 DOM 场景完成正常及失败路径验收，保存实际应用元数据和脱敏证据；真实平台能力未经验证时如实标记，不暗示离线测试已证明实发。

**测试边界:** 以已经确认的公共 CLI/任务接口为主；只有平台页面、进程终止和资源回收等必要场景增加本地测试。验收观察结果与交付行为，不绑定私有实现细节。
