# 08 — 抖音图文复用可靠任务流程，并确认全部图片

**What to build:** 使用者能够用同一任务接口发布抖音图文，准确保留图片、文字和声明，并获得与视频相同的防重发和结果核对能力。

**Blocked by:** 07 — 抖音视频完成准确填写、单次提交和作品核对

**Status:** draft — breakdown approved; pending tracker selection

**来源:** 《三平台个人账号无人值守发布》规格；用户故事 8、10、11、12、13、14、15、16、17、23、24、25、26、27、31、32；代码审计需求 R02、R03、R05、R06、R07、R10。

- [ ] 图文路径复用已稳定的抖音账号、会话、提交和只读核对能力，不维护另一套不兼容结果协议。
- [ ] 核对图片预览成功数量及失败项；图片未全部就绪、标题框先出现或处理失败时不能提交。
- [ ] 标题正文话题和显式声明按清单填写并读回；不通过默认标题或其他隐式值覆盖明确输入。
- [ ] 验证发生在上传前、填写后或提交前均阻止写入，未知浮层不被全局删除。
- [ ] 导航延迟、提交后异常和重启恢复均不重复提交；图文作品查询结果可正确匹配，不能默认沿用仅支持视频的查询条件。
- [ ] 图片部分成功、清理失败、取消等情况均从公共接口返回正确结果；离线验收不访问真实账号。

**测试边界:** 以已经确认的公共 CLI/任务接口为主；只有平台页面、进程终止和资源回收等必要场景增加本地测试。验收观察结果与交付行为，不绑定私有实现细节。
