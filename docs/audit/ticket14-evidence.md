# Ticket 14: safe diagnostics and session storage evidence

The task store keeps authored `manifest` and verified `actual_metadata` intact. It allowlists error codes, fields, messages, runtime version facts, and event details before they enter ordinary query output. A private diagnostic JSON artifact receives a unique `evidence/<job_id>/<attempt_id>/<uuid>.json` path; the event and job status retain its relative path and SHA-256 reference. Artifacts contain allowlisted facts only, never page screenshots, HAR, QR images, cookies, or raw exception text. Legacy Loguru sinks use stderr and fixed messages with exception details and local-variable diagnostics disabled.

Managed sessions and evidence use a protected Windows DACL containing the current process user's SID. The native Win32 path applies the DACL at directory creation and to managed files; it does not change the user home, repository, source session, or runtime parent ACL. Session writes use a private exclusive temporary file, validate storage-state JSON, fsync, then atomically replace the destination. A failed validation, ACL change, or replacement leaves the prior session bytes in place. On non-Windows systems, managed children use mode 0700/0600.

Evidence retention is 30 days and applies only to managed UUID JSON files under `runtime/evidence`. `TaskService.prune_evidence()` and `sau jobs prune-evidence` run cleanup explicitly outside browser stage budgets. Stored references can outlive their artifact after retention. Runtime evidence records the pinned Patchright driver and observed browser/capability versions when available. A driver regression can be checked against those events; reverting to the pinned driver/browser and rebinding a previously exported, validated storage-state file requires a fresh account identity check before publishing. This ticket does not add automatic versioned session backups or persistent-profile migration.
